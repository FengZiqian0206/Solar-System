# Colour-cycling cursor / lattice roaming

- Overview and roaming are fixed at 50³ (125,000 grid points). The disabled density slider stays disabled after startup; old density events cannot rebuild the scene.
- Desktop mouse cursor: 16px flat colour-cycling dot, 70% opacity and a four-second colour cycle; “Double-click to start” fades on a five-second cycle after an initial five-second delay.
- Double-click or double-tap enters fullscreen and hides names and leader lines. Touch browsers can use the viewport-filling CSS mode when native element fullscreen is unavailable or refused. Spawn snaps to the existing grid vertex nearest Earth's current centre. Earth is sampled only on entry; subsequent orbital motion does not move the player.
- Hold physical W or the on-screen W button to move along the camera's viewing direction at 6 world units/second (33% faster than 4.5). Continuous travel drives a smooth third-person camera; the highlighted position is always snapped to an existing lattice vertex. Travel is clamped to the cube's ±26 bounds. Releasing one input does not cancel another held input. Pointer release/cancel/lost capture, key release, blur, hidden tab and exit clear the corresponding movement source.
- All currently coloured cluster points use the same continuous radial size curve: 18 CSS pixels at the centre, tapering towards 4 pixels at the edge. The selected point has no special minimum or size multiplier. Size follows the continuous travel centre instead of jumping between selected vertices; only the barely tinted outer fringe blends back into the scene. The selected point retains 70% opacity and a four-second colour cycle. The group's radius is 2.1 grid steps; its 95% colour-sharing core ends at 1.05 steps. Each cell ramps toward its target with a 0.22-second rise time constant and a slower 6-second fade time constant (about 0.5 seconds to 90% arrival, 14 seconds to fade by 90%). Base coordinates and the selected point stay on the grid; nearby points can render off-grid under repulsion.
- Influenced points retain an opacity floor of 55% times influence (about 52% for the closest settled neighbours); already-opaque points are not dimmed. Departed trail points keep their underlying size and gradually fade back to their original colour. There is no extra sphere, glow or deleted point. Re-entry clears all previous influence.
- Repulsion surrounds the colour core out to 5.5 grid steps. It ramps outward beyond 2.1 steps, reaches at most 1.8 steps of displacement, then tapers to zero at the boundary. Offsets ease toward their targets with a 0.18-second time constant and return with a 0.9-second time constant (about 2.1 seconds to recover 90%). The selected point is explicitly pinned in the shader. Repulsion follows continuous travel independently of the much longer colour trail. Overview ignores offsets immediately; re-entry clears them.
- Overview horizontal dragging uses positive yaw delta. Roaming mouse-look keeps negative yaw delta and the existing vertical direction and sensitivity. Roaming yaw/pitch wrap continuously with no angle clamp; a quaternion orbit prevents world-up flips at the poles. Overview rotation is unchanged.
- Camera starts 40 units behind the player (25% farther than 32), mouse movement turns without dragging, wheel changes distance between 6 and 90, and Esc/Exit restores overview. On touch devices, dragging the view turns independently of holding the W button with another finger. Existing overview appearance, orbital data, charts and saved overview camera/follow state remain unchanged.
- The monochrome 56×56px W key sits at bottom-right, with the small English hint “HOLD W TO / MOVE FORWARD” on its right. Pointer or keyboard input lights the key and depresses it by 2px. Safe-area padding protects the controls; Exit is at top-right. Holding the key uses pointer capture, with native selection/context-menu gestures disabled only on that key. Space/Enter also work when it has keyboard focus.
- Uses existing Three.js and native fullscreen/pointer lock; no additional runtime dependency. Desktop pointer lock is requested first, within the double-click gesture, before fullscreen. Roaming reads relative `mousemove` events. Pointer-lock refusal falls back to ordinary movement plus slow continuous turning within 24 pixels of a screen edge; clicking the scene retries lock. Desktop fullscreen refusal releases any already acquired lock, leaves overview usable and displays retry guidance. Coarse touch input skips pointer lock.
