# Monochrome cursor / lattice roaming

- Overview and roaming are fixed at 50³ (125,000 grid points). The disabled density slider stays disabled after startup; old density events cannot rebuild the scene.
- Overview mouse cursor: 16px black/grey/white linear-gradient dot, 70% opacity, with a four-second monochrome inversion cycle. The roaming point cloud keeps its existing colour cycle. “Double-click to start” has a thin diagonal-plus-horizontal SVG leader anchored at the cursor centre, matching the planet-label style. Leader and text fade together on a five-second cycle after an initial five-second delay. Near the right/top edges they mirror left/down; neither intercepts pointer input.
- After the splash has disappeared and rendering has loaded, the page automatically enters roaming once per load, hiding names and leader lines. It tries native fullscreen and falls back to the viewport-filling CSS mode when permission is unavailable. The first real click/tap or W key can upgrade the existing session to native fullscreen without resetting travel. After exit, overview stays visible until a double-click/double-tap. An `enteredOnce` guard also prevents the splash timer from restarting an early manual session that the user already exited. Spawn snaps to Earth's nearest grid vertex; subsequent orbital motion does not move the player.
- Hold physical W or the on-screen W button to move along the camera's viewing direction at 6 world units/second (33% faster than 4.5). Continuous travel drives a smooth third-person camera; the highlighted position is always snapped to an existing lattice vertex. Travel is clamped to the cube's ±26 bounds. Releasing one input does not cancel another held input. Pointer release/cancel/lost capture, key release, blur, hidden tab and exit clear the corresponding movement source.
- All currently coloured cluster points use the same continuous radial size curve: 18 CSS pixels at the centre, tapering towards 4 pixels at the edge. The selected point has no special minimum or size multiplier. Size follows the continuous travel centre instead of jumping between selected vertices; only the barely tinted outer fringe blends back into the scene. The selected point retains 70% opacity and a four-second colour cycle. The group's radius is 2.1 grid steps; its 95% colour-sharing core ends at 1.05 steps. Each cell ramps toward its target with a 0.22-second rise time constant and a slower 6-second fade time constant (about 0.5 seconds to 90% arrival, 14 seconds to fade by 90%). Base coordinates and the selected point stay on the grid; nearby points can render off-grid under repulsion.
- Influenced points retain an opacity floor of 55% times influence (about 52% for the closest settled neighbours); already-opaque points are not dimmed. Departed trail points keep their underlying size and gradually fade back to their original colour. There is no extra sphere, glow or deleted point. Re-entry clears all previous influence.
- Repulsion surrounds the colour core out to 5.5 grid steps. It ramps outward beyond 2.1 steps, reaches at most 1.8 steps of displacement, then tapers to zero at the boundary. Increasing forces respond with a 0.18-second time constant; diminishing forces recover with a 1.2-second time constant (about 2.8 seconds to recover 90%, shortened from 6.9 seconds). This brief return also applies while a cell is still inside the force field. The selected point is explicitly pinned in the shader. Repulsion follows continuous travel independently of the long colour trail. Overview ignores offsets immediately; re-entry clears them.
- Overview horizontal dragging uses positive yaw delta. Roaming mouse-look keeps negative yaw delta and the existing vertical direction and sensitivity. Roaming yaw/pitch wrap continuously with no angle clamp; a quaternion orbit prevents world-up flips at the poles. Overview rotation is unchanged.
- Camera starts 48 units behind the player (20% farther than 40), mouse movement turns without dragging, wheel changes distance between 6 and 90, and Esc/Exit restores overview. On touch devices, dragging the view turns independently of holding the W button with another finger. Existing overview appearance, orbital data, charts and saved overview camera/follow state remain unchanged.
- The monochrome 56×56px W key sits at bottom-right, with the small English hint “HOLD W TO / MOVE FORWARD” on its right. Pointer or keyboard input lights the key and depresses it by 2px. Safe-area padding protects the controls; Exit is at top-right. Holding the key uses pointer capture, with native selection/context-menu gestures disabled only on that key. Enter also works when it has keyboard focus.
- Space triggers a one-shot twenty-four-second vortex while roaming. The wide physical SPACE key is at bottom-left, with “看看会发生什么 / SEE WHAT HAPPENS”; it can be tapped while another finger holds W. Triggering clears all forward input and disables both action keys. Physical W cannot resume translation, but camera look/zoom and Exit still work. Enter remains the focused W button's keyboard alternative; Space always invokes the vortex.
- Vortex progress uses uncapped frame elapsed time independently of capped movement steps. The continuous cluster centre, orbital data, tint and repulsion offsets freeze at the trigger. Incoming particles retain their normal opacity and size until entering the original coloured-core radius (2.1 grid steps). Inside, they spiral inward exponentially and fade over 1.2 seconds. The original coloured core now splits into two opposite world-Y jets instead of fading in place. Each point travels 12–16 world units over twelve seconds, using a normalized exponential ease-out: speed starts at about 2.6–3.5 units/second and decreases to 0.24–0.32. Existing hemisphere positions select the jet direction; fixed seeds split points near the equator. A mild opposite twist and 18% transverse spread start continuously from the existing positions. Opacity stays unchanged through 75% of each point's travel, then fades only over the remaining distance. There is no global fade applied to the surrounding cloud. Radial motion depends on initial radius: farther particles move inward more slowly before entry. A much stronger differential twist winds the stream repeatedly, and local flattening preserves its controlled radial distance. The farthest cube corner plus the existing offset bound sets the sweep scale, ensuring entry by 22 seconds and complete fade by 24 seconds even near the cube boundary. After completion, a fresh Space press or a click/tap anywhere exits both roaming and native/CSS fullscreen. Repeated Space events do not dismiss the animation. Capture-phase dismissal includes disabled HUD-key areas; a 500ms entry guard consumes the closing gesture without immediately reopening or activating overview controls. Exit/re-entry restores the original scene. No new particles, draw calls, textures, vertex buffers or runtime dependencies are introduced.
- Uses existing Three.js and native fullscreen/pointer lock; no additional runtime dependency. Pointer lock is requested only with a real activation on automatic entry or upgrade, and always before requesting fullscreen. Roaming reads relative `mousemove` events. Pointer-lock refusal falls back to ordinary movement plus slow continuous turning within 24 pixels of a screen edge; clicking the scene retries lock. Manual desktop fullscreen refusal releases any already acquired lock and displays retry guidance; automatic entry always has the CSS fallback. Coarse touch input skips pointer lock. Late native upgrades are cleaned up if the user has already exited.
